# 연습 경험 완성 설계

## 목표

첫 번째 후속 단계로 현재 OPIc 연습 흐름을 완성한다. 실제 OPIc 질문을 생성·표시하고, 앱 실행
중에는 이전 질문을 다시 출제하지 않으며, 완료한 세트를 자세히 요약한다. 즐겨찾기에서는 모범 문장
즉시 듣기와 녹음을 포함한 전체 연습을 모두 제공한다.

이 단계가 완료된 뒤 별도 설계 주기로 출시 준비, AI 학습 피드백 기능을 순서대로 진행한다.

## 범위

- AI 생성 결과에 실제 OPIc 질문 추가
- 일반 연습 화면에 질문 표시
- 앱 프로세스 생존 기간 동안 질문 중복 방지
- 중복 제거로 부족한 항목을 같은 제공자에 한 번 보충 요청
- 마지막 완료 세트의 질문·힌트·영어 문장·즐겨찾기 상태 요약
- 즐겨찾기 문장 TTS 즉시 재생
- 즐겨찾기 한 문장 전체 연습
- 기존 즐겨찾기 보존을 위한 Room 1→2 마이그레이션
- TTS 사용 불가 상태의 안전한 축소 동작

이번 범위에서 제외한다.

- 앱 재실행 이후까지 유지되는 질문 이력
- 연습 횟수, 점수, 연속 학습 등 장기 통계
- 녹음 파일 영구 저장
- 음성 인식, 발음 채점, 문법 교정 및 AI 피드백
- 출시 서명, 배포 자동화, 스토어 등록 자료

## 데이터 모델

### PracticeQuestion

```kotlin
data class PracticeQuestion(
    val opicQuestion: String,
    val koreanHint: String,
    val englishSentence: String,
    val category: PracticeCategory
)
```

두 AI 제공자의 생성 응답은 다음 형식을 사용한다.

```json
{
  "opic_question": "Tell me about your home.",
  "korean_hint": "나는 살고 있다 / 서울에 / ...",
  "english_sentence": "I live in Seoul, and what I like most about my home is ..."
}
```

공통 파서는 세 필드가 모두 존재하고 공백이 아니어야 유효한 항목으로 인정한다.

### FavoriteSentence

`FavoriteSentence`에 nullable `opicQuestion: String?` 열을 추가하고 Room 스키마를 버전 2로
올린다. 명시적 1→2 마이그레이션은 nullable TEXT 열을 추가하며 기존 행을 삭제하거나 다시 만들지
않는다. 기존 즐겨찾기는 질문이 없어도 힌트, 영어 문장, TTS, 녹음 연습을 계속 사용할 수 있다.

새로 저장하는 즐겨찾기는 현재 `PracticeQuestion.opicQuestion`을 함께 저장한다.

## 세션 저장소

앱의 수동 DI 컨테이너가 프로세스 메모리용 `PracticeSessionStore` 인스턴스 하나를 생성한다.
Room이나 SharedPreferences에는 세션 데이터를 기록하지 않는다.

저장소의 책임은 다음과 같다.

- 이번 앱 실행에서 이미 생성된 실제 OPIc 질문 목록 유지
- 질문 비교용 정규화: 앞뒤 공백 제거, 연속 공백 축소, 소문자 변환
- 마지막으로 완료한 세트와 항목별 즐겨찾기 상태 유지
- 앱 프로세스 종료 시 자연스럽게 전체 상태 초기화

저장소는 네트워크 호출이나 Room 접근을 하지 않는다. Repository는 질문 이력을 읽고 추가하며,
ViewModel은 완료 세트 스냅샷을 기록하고 완료 화면에서 읽는다.

## 생성 및 중복 방지 흐름

1. `PracticeSetViewModel`이 세트 생성을 요청한다.
2. Repository가 `PracticeSessionStore`에서 이미 출제된 질문을 읽는다.
3. 공통 프롬프트가 카테고리, 목표 개수, 기존 실제 질문 목록을 포함한다.
4. 선택된 Claude 또는 OpenAI 제공자 하나를 호출한다.
5. 공통 파서가 질문·힌트·영어 문장을 검증한다.
6. 기존 세션 질문 및 현재 응답 안에서 중복되는 질문을 정규화 비교로 제거한다.
7. 목표 개수보다 부족하면 같은 제공자, 같은 카테고리에 한 번만 보충 요청한다. 보충 프롬프트에는
   기존 세션 질문과 첫 응답에서 수락한 질문을 모두 포함한다.
8. 두 번째 결과에도 중복 제거를 적용하고 목표 개수를 채우면 세션 질문 이력에 추가한다.
9. 최대 두 번의 제공자 호출 뒤에도 개수가 부족하면 `InsufficientUniqueQuestions` 오류를 반환한다.

JSON 파싱 실패와 중복 보충은 별도의 추가 호출 예산을 갖지 않는다. 최초 응답이 파싱 불가능하면
두 번째이자 마지막 호출을 수행한다. 두 번째 응답도 파싱 실패하거나 고유 질문 수가 부족하면 즉시
typed error를 반환한다. 따라서 세트 생성 한 번의 원격 호출 수는 항상 최대 2회다.

인증, 요청 제한, 네트워크 및 기타 제공자 오류는 자동 재시도하지 않으며 다른 제공자로 전환하지
않는다. 실패한 생성에서는 일부 결과를 세션 질문 이력에 추가하지 않는다.

## 일반 연습과 완료 화면

일반 연습 화면은 다음 순서로 표시한다.

1. 실제 OPIc 질문
2. 영어 어순의 한국어 힌트
3. 녹음 시작·중지
4. 내 녹음 듣기와 모범 문장 TTS
5. 영어 모범 문장과 즐겨찾기 토글
6. 다음 문제

마지막 문제를 마치면 ViewModel이 완료 당시 질문 목록과 각 항목의 즐겨찾기 여부를
`PracticeSessionStore`에 불변 스냅샷으로 기록한다. 완료 화면은 route에 전체 문장을 넣지 않고 이
스냅샷을 읽어 다음을 표시한다.

- 연습한 총 문장 수
- 즐겨찾기한 문장 수
- 각 항목의 실제 질문, 한국어 힌트, 영어 문장
- 각 항목의 즐겨찾기 표시
- 홈으로 이동 버튼

완료 스냅샷이 없는 상태로 화면을 복원하면 오류 대신 홈으로 이동할 수 있는 빈 상태 안내를
표시한다.

## 즐겨찾기 복습과 전체 연습

즐겨찾기 카드에는 다음 세 동작이 있다.

- `바로 듣기`: 카드의 영어 문장을 TTS로 재생
- `전체 연습`: 즐겨찾기 한 문장 전용 연습 화면으로 이동
- `삭제`: 기존 즐겨찾기 삭제

전용 화면은 일반 연습과 같은 재사용 가능한 `SpeakingPracticeContent`를 사용한다. 공통 Composable은
화면 상태를 직접 소유하지 않고 질문·힌트·문장·녹음 상태와 콜백을 입력받는다. 일반 세트와
즐겨찾기 연습은 각각의 ViewModel에서 상태와 수명주기를 관리한다.

즐겨찾기 전체 연습 흐름은 질문, 힌트, 녹음, 내 녹음 재생, 모범 문장 듣기, 완료 순서다. 질문이
없는 기존 즐겨찾기는 `저장된 질문 없음 — 힌트를 보고 답해보세요.`를 표시하고 나머지 연습 기능은
동일하게 제공한다. 완료하면 즐겨찾기 목록으로 돌아간다.

즐겨찾기 항목 ID만 navigation 인자로 전달하고, 전용 ViewModel이 Room에서 해당 항목을 조회한다.
항목이 삭제되었거나 존재하지 않으면 목록으로 돌아갈 수 있는 오류 상태를 표시한다.

## 오디오 오류와 축소 동작

TTS 추상화는 초기화 및 언어 지원 가능 상태를 노출한다. TTS가 초기화되지 않거나 US English를
지원하지 않으면 앱은 다음처럼 동작한다.

- `바로 듣기`와 `모범 문장 듣기` 버튼 비활성화
- 텍스트 문장과 `이 기기에서는 영어 음성 재생을 사용할 수 없습니다.` 안내 표시
- 녹음, 힌트 읽기, 즐겨찾기 삭제 등 나머지 기능 유지

녹음 권한이 거부된 경우에는 기존과 동일하게 녹음 없이 질문·힌트·모범 문장과 사용 가능한 TTS로
연습할 수 있다. 화면을 떠나거나 항목을 완료하면 즐겨찾기 연습용 임시 녹음 파일도 삭제한다.

## 의존성 연결

`AppContainer`는 다음 공유 객체와 팩토리를 제공한다.

- 단일 `PracticeSessionStore`
- 기존 `PracticeRepository`, `FavoriteRepository`, `AiSettingsStore`
- 화면별 `SpeechPlayer`, `VoiceRecorder`, `VoicePlayer`, 임시 녹음 파일

새 DI 프레임워크는 도입하지 않는다. `PracticeRepository`는 AI 제공자와 설정 저장소 외에 세션
저장소를 주입받는다. 완료 화면과 일반 연습 ViewModel도 동일한 세션 저장소를 사용한다.

## 테스트 전략

### 단위 테스트

- Claude/OpenAI 공통 결과에서 `opic_question` 파싱
- 질문 누락, 공백, 잘못된 JSON 거부
- 기존 질문 목록이 생성 및 보충 프롬프트에 포함됨
- 대소문자, 앞뒤 공백, 연속 공백 차이가 있는 질문을 중복으로 판정
- 현재 응답 내부 중복과 이전 세션 중복 제거
- 수량 부족 시 같은 제공자에 정확히 한 번 보충 요청
- 최대 두 번 호출 후 부족하면 `InsufficientUniqueQuestions`
- JSON 파싱 실패와 중복 보충을 합쳐 최대 두 번만 호출
- 제공자 오류 무재시도 및 coroutine 취소 재전파
- 성공 시에만 세션 질문 이력에 원자적으로 추가
- 완료 세트 및 즐겨찾기 스냅샷 저장·조회
- 질문 없는 기존 즐겨찾기 fallback 상태
- 즐겨찾기 전체 연습 ViewModel의 녹음·재생·완료 상태
- TTS 사용 불가 상태에서 재생 호출 방지

### Room 및 Android 계측 테스트

- Room 1→2 마이그레이션 후 기존 즐겨찾기 필드와 행 보존
- 새 즐겨찾기의 질문 저장·조회
- 일반 연습 화면의 실제 질문 표시
- 즐겨찾기 카드의 바로 듣기와 전체 연습 이동
- 질문 없는 기존 즐겨찾기 안내
- 즐겨찾기 전체 연습의 녹음·재생 흐름
- 완료 화면의 목록, 즐겨찾기 표시와 총개수
- TTS 사용 불가 시 버튼 비활성화와 안내

## 완료 기준

- JVM 단위 테스트 전체 통과
- Android 계측 및 Compose 테스트 전체 통과
- Room 1→2 마이그레이션 테스트 통과
- `assembleDebug`와 `lintDebug` 성공, lint 오류 0건
- 같은 앱 실행에서 성공한 이전 질문이 다음 세트 프롬프트에 전달됨
- 앱 프로세스를 새로 시작하면 질문 이력이 비어 있음
- 생성 한 번당 원격 API 호출이 어떤 실패·중복 조합에서도 최대 2회
- 기존 즐겨찾기 행이 손실되지 않고 질문 없는 fallback으로 계속 사용 가능
- TTS와 녹음 중 하나가 없어도 텍스트 중심 연습 흐름 유지
